# Production gap analysis

**Audit baseline at `dc8a58d`.** M1 subsequently delivered tenant ownership and named decisions. See [current progress](PROGRESS.md) for verification and remaining gaps.

**Retain the existing repository.** The strongest production assets are the Go transaction that accepts an invoice, the job claim and completion protocol, the deterministic validator and the review client that already uses them. The largest gap is ownership. Today a short-lived browser workspace owns business records, while a single actor label represents every reviewer. ## Component disposition

KEEP applies to the named component within its current responsibility. REFACTOR identifies usable code with a production gap. REPLACE applies only to a specified production mechanism. ADD identifies functionality missing from the audited repository.

| Component | Disposition | Evidence today and required production work |
|---|---|---|

Preserve the single writer, decimal strings and human decision endpoint. [Rules](../services/gateway/rules.go) · [Routes](../services/gateway/invoices.go#L429) |
| Validation and approval policy | **REFACTOR** | AED standard-rate arithmetic, a one-cent tolerance, TRN format, duplicates and a fictional AED 10,000 threshold are implemented. ## Risks in migration order

Priorities describe the impact of taking the current behavior into customer production. P0 blocks customer data or decisions. P1 blocks the relevant cutover or pilot.

| Priority and risk | Why it matters here | Evidence required to close |
|---|---|---|
| **P0 · Loss of invoice and audit history** | Reset marks a workspace expired. The gateway's periodic delete cascades through invoices, revisions and audit. Removing direct audit UPDATE/DELETE grants cannot prevent that cascade. [Reset](../services/gateway/metrics.go#L35) · [Purge](../services/gateway/main.go#L294) | Customer data and audit survive logout, expiry and demo purge. Prove restore and authorized retention/deletion against an agreed policy. |
| **P0 · Cross-tenant access or unattributable approval** | Public scope comes from a cookie. The preview catalog and policy seed are global. The worker trusts an internal service credential. Generic reviewer identities give no evidence of individual authority. [Preview](../services/gateway/preview.go) · [Policy seeder](../services/ai/app/seed.py) · [Review](../services/gateway/invoices.go#L344) | Two tenant fixtures, named users and denied-access tests spanning API, SQL, jobs, blobs, policies and metrics. Concurrent, revoked and unauthorized decisions must fail. |
| **P0 · Untrusted source or unsupported invoice treated as valid** | The worker currently receives a fixture name. Waiting on a parsing thread for 60 seconds does not terminate a native parser still running. The benchmark uses labeled layouts. Printed and human-corrected fields require distinct provenance. [Worker](../services/ai/app/worker.py#L18) · [Benchmark](../evaluation/REPORT.md) | Bind an immutable object version, quarantine input, enforce process-level limits, verify evidence, and route unsupported cases to human review. Qualify the supported document set before pilot. |
| **P1 · Lost or repeated work at SQS cutover** | Current consumers may acknowledge a busy delivery because the SQL outbox can publish again. The dispatcher reschedules eligible outbox rows every ten seconds. Copying those rules into SQS can amplify messages or strand work. [Dispatch](../services/gateway/jobs.go#L16) · [Acknowledgment logic](../services/ai/app/worker.py#L18) | Exercise duplicate sends, late callbacks, visibility expiry, failed acknowledgment, bounded retries, DLQ reconciliation and rollback with jobs in flight. Demonstrate one committed result per accepted attempt. |
| **P1 · Tenant throughput and availability** | All mutations lock one workspace row. The dispatcher publishes one eligible job per tick per process. The UI can fetch every invoice page on refresh. Neither multi-user contention nor a tenant-sized backlog was measured. [Lock](../services/gateway/invoices.go#L51) · [Dispatcher](../services/gateway/jobs.go#L16) · [UI](../apps/web/app/page.tsx#L81) | Measure queue age, lock waits, query latency and bounded UI paging under agreed concurrent workloads. Narrow locks without weakening duplicate checks. |
| **P1 · Operational blind spots and shared credentials** | Readiness checks a specific migration and Redis. It does not establish worker progress. Compose disables database TLS, and service DNS, local file mounts and privileged seed credentials are environment-specific. [Readiness](../services/gateway/main.go#L207) · [Compose](../compose.yaml) | Prove private routing, rotated secrets, worker progress alarms, database restore, trace correlation and release rollback in staging. |

Two verification gaps matter before adding consumers or a provider. The private FastAPI schema lists the authorization header as optional and omits the enforced 403 response. The success schema for `/retrieve-answer` is unconstrained. Define the actual security and result types and test consumer behavior. The evaluation reporter checks that all cases ran and calculates metrics, but does not enforce minimum quality thresholds. Add a release gate on the agreed metrics for supported document types. [AI contract](../packages/contracts/ai.openapi.json) · [Authentication and handlers](../services/ai/app/api.py) · [Evaluation reporter](../scripts/evaluate.py#L26)

The highest-impact contract changes are a required `sample_id`, worker claims returning that same identifier, mock-only run storage and response labels, and workspace-scoped idempotency. The rollout and compatibility rules for each are in the [migration plan](PRODUCTION_MIGRATION_PLAN.md).
